# Yandex Music → Apple Music

Перенос плейлистов из Яндекс Музыки в Apple Music с проверкой дублей и сохранением песен в медиатеку.

Скрипт ищет соответствующие записи в каталоге Apple Music, дополняет существующие плейлисты и создаёт отсутствующие. Уже добавленные песни пропускаются. Исходные плейлисты и порядок существующих песен не меняются. Аудиофайлы не скачиваются.

Используются неофициальная библиотека Яндекс Музыки и внутренний API веб-плеера Apple Music. При изменениях сервисов подключение может перестать работать. Проект не связан с Яндексом или Apple.

## Требования

- Python 3.11 или новее и [uv](https://docs.astral.sh/uv/getting-started/installation/).
- Аккаунт Яндекса с доступом к собственным плейлистам.
- Активная подписка Apple Music.
- Chrome, Edge или Firefox для получения cookie веб-плеера Apple Music.

Платный аккаунт Apple Developer не нужен. Для отображения изменений в приложении «Музыка» включите «Синхронизацию медиатеки».

## Установка

Скачайте репозиторий или клонируйте его, откройте терминал в папке проекта и установите зависимости:

```sh
uv sync --locked
```

На macOS с Homebrew установить uv можно командой `brew install uv`.

## Настройка плейлистов

Соответствия задаются в `PLAYLIST_MAPPING` в файле `transfer_music.py`. В каждой паре сначала идёт название плейлиста Яндекса, затем название плейлиста Apple Music. По умолчанию:

```python
PLAYLIST_MAPPING = (
    ("общий", "all"),
    ("cry", "cry"),
    ("get popped", "get popped"),
)
```

Замените названия своими или измените число пар. Все команды используют этот список, включая сохранение в медиатеку.

Названия сравниваются без учёта регистра и пробелов по краям. Если найдено несколько одноимённых плейлистов, скрипт остановится. Целевой плейлист должен быть доступен для редактирования.

В Яндексе читаются собственные плейлисты. Для чужого плейлиста сначала создайте свою копию. Коллекция «Мне нравится» отдельно не обрабатывается.

## Подключение Яндекс Музыки

```sh
uv run python transfer_music.py auth-yandex
```

Откройте страницу, которую покажет скрипт, введите код и подтвердите доступ. Код ограничен по времени, поэтому не откладывайте подтверждение. Пароль вводится только на странице Яндекса. Дождитесь сообщения о сохранении доступа.

Если вход по коду недоступен, получите OAuth-токен по [инструкции библиотеки](https://ym.marshal.dev/token/) и вставьте его через скрытый ввод:

```sh
uv run python transfer_music.py auth-yandex --manual
```

Обычный токен произвольного приложения Яндекс OAuth не заменяет токен Яндекс Музыки.

## Подключение Apple Music

1. Откройте [music.apple.com](https://music.apple.com/) в Chrome, Edge или Firefox и войдите в нужный аккаунт.
2. Откройте медиатеку и убедитесь, что видите свои плейлисты.
3. Откройте инструменты разработчика: `⌘⌥I` на macOS, `F12` или `Ctrl+Shift+I` на Windows/Linux.
4. В Chrome/Edge перейдите в **Application → Storage → Cookies → https://music.apple.com**. В Firefox откройте **Storage → Cookies**.
5. Найдите cookie `media-user-token` и скопируйте только её значение, без имени и кавычек.
6. Запустите команду и вставьте значение:

```sh
uv run python transfer_music.py auth-apple
```

Ввод не отображается. Скрипт самостоятельно получает служебный Bearer-токен из публичного кода веб-плеера, проверяет подписку и сохраняет пользовательский токен локально.

В Safari нет вкладки Application, поэтому шаги для Chrome/Edge в нём не подходят. Для этой инструкции используйте один из перечисленных браузеров. Вход в приложение «Музыка» не заменяет вход на сайт.

## Запуск

Сначала проверьте доступ и выполните пробный поиск:

```sh
uv run python transfer_music.py check
uv run python transfer_music.py --dry-run
```

`check` читает исходные и целевые плейлисты без изменений. `--dry-run` дополнительно ищет совпадения и записывает CSV-отчёт. Строки `would_add` показывают, какие песни будут добавлены.

После просмотра отчёта запустите перенос:

```sh
uv run python transfer_music.py
```

Новые песни добавляются в конец плейлистов в порядке источника. Отсутствующий плейлист создаётся при первом добавлении. После обработки всех плейлистов скрипт отдельно сохраняет их песни в медиатеку Apple Music, включая песни, добавленные туда до запуска скрипта.

Не запускайте несколько копий одновременно и не редактируйте целевые плейлисты во время переноса: между чтением состава и добавлением может появиться дубль.

### Только сохранение в медиатеку

Чтобы сохранить песни из настроенных целевых плейлистов без повторного переноса из Яндекса:

```sh
uv run python transfer_music.py --dry-run save-library
uv run python transfer_music.py save-library
```

Уже сохранённые песни пропускаются. Одна запись из нескольких плейлистов добавляется один раз. Это действие соответствует «Добавить в медиатеку», а не «Избранное» или загрузке для офлайн-прослушивания.

Ответ `202 Accepted` означает принятие запроса, но не завершение операции. Скрипт перечитывает медиатеку и проверяет появление песен. Если синхронизация ещё не завершилась, он сообщает об этом и не повторяет добавление вслепую.

## Сопоставление и дубли

Для проверки используются каталожный ID Apple Music, ISRC (код записи) и метаданные. При отсутствии общего идентификатора должны совпасть нормализованные название, состав исполнителей и длительность с допуском 3 секунды. Разные известные ISRC и известные clean/explicit версии различаются.

При нескольких совпадениях предпочтение получает исходный альбом. Если остаются разные подходящие записи, автоматический выбор пропускается. Похожие названия сами по себе не считаются совпадением. Дубли проверяются отдельно в каждом плейлисте, а перед сохранением в медиатеку учитываются все настроенные плейлисты.

Совпадения могут быть пропущены из-за транслитерации, разного написания имён, отсутствия длительности или отличий между изданиями. Поиск выполняется в регионе аккаунта Apple Music. Недоступные в этом регионе песни не переносятся. Существовавшие ранее дубли не удаляются.

## Отчёты и коды завершения

По умолчанию отчёты сохраняются рядом со скриптом в `migration-report-<дата-время>.csv`. Для своего имени используйте `--report result.csv`. Существующий файл не перезаписывается. Результаты обработки записываются по мере выполнения.

| Статус переноса | Значение |
| --- | --- |
| `added` | Apple подтвердил добавление в плейлист |
| `would_add` | План добавления при пробном запуске |
| `already_present` | Песня уже есть или учтена ранее в текущем проходе |
| `not_found` | Уверенное совпадение не найдено |
| `ambiguous` | Несколько разных подходящих записей |
| `invalid_metadata` | Нет названия или исполнителя в источнике |
| `error` | Обработка остановлена из-за ошибки запроса |

Для медиатеки создаётся отдельный отчёт со статусами `already_in_library`, `already_scheduled`, `library_would_add`, `library_add_requested`, `no_catalog_id` и `error`. Локальные записи без каталожного ID не заменяются случайными версиями из каталога.

Коды завершения: `0` — обработка завершена без пропусков, `2` — есть песни для ручной проверки, `1` — ошибка, `130` — остановка через Ctrl+C. Код `2` не отменяет уже выполненные добавления.

## Ошибки и повторный запуск

Перед каждым запуском состав плейлистов читается заново, поэтому подтверждённые ранее песни пропускаются.

- **401/403:** проверьте подписку и повторите авторизацию соответствующего сервиса. Для Apple скопируйте cookie из текущей сессии браузера.
- **429:** запросы Apple разделены паузой не менее 1,5 секунды. При ограничении чтения скрипт ждёт 60, 120 и 240 секунд либо дольше по `Retry-After`. Автоматически повторяются только запросы чтения.
- **Сетевая ошибка при добавлении:** Apple мог принять запрос, даже если ответ не дошёл. Дождитесь синхронизации, проверьте плейлист и только затем запускайте скрипт снова. Запросы записи автоматически не повторяются.
- **Плейлист не найден:** проверьте аккаунт, название и владельца исходного плейлиста.
- **Не удалось получить Bearer-токен:** сайт Apple недоступен или его структура изменилась. Не используйте случайные токены со сторонних сайтов.

## Безопасность

Токены хранятся в `.secrets.json` рядом со скриптом. На macOS/Linux файл создаётся с правами `0600`. На Windows ограничьте доступ к папке средствами системы. Для удаления сохранённого доступа удалите `.secrets.json`. Это не отзывает токены на стороне сервисов.

Не публикуйте токены, cookies, отчёты или скриншоты с их значениями. `.gitignore` исключает локальные секреты, CSV-отчёты, журналы и кэши. Исключения Git не защищают файлы, которые уже попали в коммит. Если токен был опубликован, отзовите его у сервиса и получите новый.

Можно передать доступ через переменные окружения `YANDEX_MUSIC_TOKEN` и `APPLE_MUSIC_USER_TOKEN`. Они имеют приоритет над файлом. Необязательная `APPLE_MUSIC_BEARER_TOKEN` принимает служебный токен веб-плеера, не JWT приложения Apple Developer. Обычно она не нужна.

## Разработка

```sh
uv sync --locked
uv run python -m unittest discover -s tests -v
uvx ruff check .
```

Тесты работают без личных аккаунтов и сетевых запросов. Они покрывают пагинацию, сопоставление записей, повторный запуск, сохранение в медиатеку, ограничения частоты запросов и неопределённый результат записи.
